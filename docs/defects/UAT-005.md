# Defect Report — UAT-005

| Field | Value |
|---|---|
| **Defect ID** | UAT-005 |
| **Title** | LIKHA metadata extraction sectionCount field not populated from fixture PDF |
| **Test Case** | UAT-005 — LIKHA metadata extraction accuracy ≥80% on fixture first pages |
| **Severity** | Medium |
| **Priority** | Medium |
| **Module** | LIKHA — L003 (Metadata Parser agent) |

## Steps to Reproduce

1. Upload `tests/fixtures/likha/sample-ordinance.pdf` via LIKHA batch upload.
2. Run the LIKHA pipeline (OCR Extractor → Metadata Parser).
3. Open the record's extracted metadata in the archive detail / verification view.
4. Compare the 4 extracted fields (ordinanceNumber, seriesYear, title, sectionCount) against ground truth.

## Expected Result

All 4 metadata fields populated with ≥80% accuracy (at least 3.2/4 fields correct). The `sectionCount` field should contain a non-null integer representing the number of sections in the ordinance.

## Actual Result

3 of 4 fields extracted correctly (75% accuracy):

| Field | Expected | Extracted | Match |
|---|---|---|---|
| ordinanceNumber | 5 | 5 | Yes |
| seriesYear | 2023 | 2023 | Yes |
| title | "An ordinance revising the schedule of business permit fees" | "An ordinance revising the schedule of business permit fees" | Yes |
| sectionCount | >0 (non-null) | null | **No** |

Observed accuracy: **75%** (below the 80% threshold).

## Possible Root Cause

The Metadata Parser agent (L003) uses the LLM to extract structured metadata from OCR text. The `sectionCount` field likely requires the model to count section markers (e.g., "Section 1.", "Section 2.") in the extracted text. On this fixture PDF, the OCR text may not contain clearly delineated section headers, or the parser prompt does not instruct the model to count sections from the body text. The model correctly extracted the ordinal fields (number, year, title) but returned null for the count-based field.

## Recommended Fix

1. **Parser prompt enhancement**: Add explicit instruction in the metadata parser prompt to count occurrences of "Section N" patterns in the OCR text and populate `sectionCount` accordingly.
2. **Fallback heuristic**: If the LLM returns null for sectionCount, apply a regex fallback (`/(Section\s+\d+)/gi`) on the OCR text to count section markers.
3. **Caveat**: This is observed evidence on 1 fixture. Statistical validation of the ≥80% target requires the full LGU pilot batch (349 ordinances). A single-field miss on one fixture may still yield ≥80% across a larger corpus.

## Workaround

Users can manually enter the section count during the HITL verification step (L004). The side-by-side verification panel allows editing all metadata fields before approval.
